# Тестирование

## Цель

Убедиться, что функция `quadratic(a, b, c)` корректно возвращает действительные корни квадратных и линейных уравнений и обрабатывает граничные случаи.

## Инструменты и метод

- **Unit-тестирование:** Google Test, макросы `TEST`, `ASSERT_EQ`, `EXPECT_DOUBLE_EQ`, `EXPECT_NEAR`, `EXPECT_TRUE`, `EXPECT_FALSE`, `EXPECT_THROW`.
- **Ручное тестирование:** запуск консольной программы с заданными коэффициентами и сравнение результата с вычисленным заранее ответом.
- **Подход:** разбиение входных данных на классы эквивалентности и проверка граничных случаев.

В диалоге пользователь подтвердил, что **12 тестов проходят**. Полный актуальный набор из 12 тестов в этой документации не воспроизводится, поскольку после добавления новых проверок весь окончательный файл не был показан. Источник истины — `test_quadratic.cpp` и вывод запуска тестов.

## Проверяемые сценарии

| Сценарий | Пример | Ожидаемое поведение |
|---|---|---|
| Два рациональных корня | `(5, -3, -2)` | `-0.4`, `1` |
| Кратный корень | `(1, -2, 1)` | `1` |
| Два целых корня | `(1, -5, 6)` | `2`, `3` |
| Иррациональные корни | `(1, 0, -2)` | `-√2`, `√2` |
| Отрицательный дискриминант | `(1, 0, 1)` | Пустой вектор |
| Нулевой корень без отрицательного знака | `(1, 0, 0)` | `+0.0` |
| Округление дискриминанта | `(1, 0.2, 0.01)` | Один корень `-0.1` |
| Линейное уравнение | `(0, 2, -4)` | `2` |
| Несовместное вырожденное уравнение | `(0, 0, 5)` | Пустой вектор |
| Бесконечно много решений | `(0, 0, 0)` | `std::invalid_argument` |
| Два отрицательных корня | `(1, 5, 6)` | `-3`, `-2` |

Перечисленные случаи взяты из присланных тестов и последующего обсуждения. Фактическое число сценариев и их точные имена следует сверить с окончательным файлом.

## Пример запуска автоматизированных тестов

Если проект настроен через CMake и Google Test:

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

**Важно:** `ctest` работает, если тесты зарегистрированы в `CMakeLists.txt` (например, через `add_test` или `gtest_discover_tests`). Если регистрация не настроена, запускайте непосредственно собранный исполняемый файл тестов. Используйте команду, соответствующую конфигурации репозитория.

## Критерии приёмки

1. Проект успешно собирается.
2. Все имеющиеся автоматизированные тесты проходят.
3. Для проверенных случаев корни совпадают с ожидаемыми с корректным допуском для `double`.
4. Случаи без корней и с бесконечным количеством решений обрабатываются согласно контракту.
5. Тесты и исходный код доступны в репозитории, а в истории коммитов видно добавление тестов.

## Документирование результатов

Для отчёта лабораторной №4 используйте таблицу со столбцами:

| № | Название | Шаги воспроизведения | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|---|
| 1 | Два корня | Запустить программу; ввести `1 -5 6` | `2`, `3` (в любом порядке) | Заполнить после запуска | Заполнить после запуска |
| 2 | Нет действительных корней | Запустить программу; ввести `1 0 1` | Сообщение об отсутствии корней | Заполнить после запуска | Заполнить после запуска |
| 3 | Линейный случай | Запустить программу; ввести `0 2 -4` | `2` | Заполнить после запуска | Заполнить после запуска |

Результаты ручного тестирования не следует подменять результатами Google Test: это разные виды проверки.
